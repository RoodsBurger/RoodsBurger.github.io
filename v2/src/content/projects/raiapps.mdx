Toucan is a household budgeting and investing app fed by bank, card and brokerage data through Plaid, and RaiClimbing is a training tracker for climbing. Both hand part of the work to an LLM, which is risky around money and training loads. So code computes the figures, the model only writes about them, a server-side validator decides what reaches the screen, and anything binding waits for a person. I built both in 2026 for my own use.

## Toucan

Toucan started in July as RaiBudget, a budgeting app for me, and grew into one my household shares. It runs on macOS, iOS and Android from one Flutter codebase. Members share budgets, goals, an activity feed, a spending report and an Invest tab, and each can keep accounts private, with their own budgets and reports that nobody else sees.

Every screen follows a design system I wrote for it. A dark band holds the page's one figure and one small chart, and a light sheet under it holds the rows. The band's curve runs as one line from page to page, so a swipe between tabs slides along it, and every band chart reads by touch. Budgets stand as a range of hills, one per category. The clips follow this site's light or dark theme, as the app does.

The back end moved from Supabase to AWS in October. Postgres runs on RDS with row-level security on every table, behind PostgREST on Lambda, and the app talks only to that API. It checks for changes every 30 seconds, so another member's edit or a bank sync shows within half a minute. Plaid's access tokens are sealed with a key only the Plaid functions can use, and reading household data or secrets from the AWS console takes a deliberate change that emails an alert. It runs for about $17 a month.

The Analysis tab is a spending report written by a worker that runs every 15 minutes on Fargate. Code builds every fact first: budget pace, recurring charges, savings rate, net worth and where the month's income went. One OpenAI call then writes only words: a one-line summary, a short note per chart and a few recommendations. Every amount and percentage in the reply has to trace back to a figure it was given, or the reply is retried once and then dropped. Member names and people paid directly are swapped for aliases before the call.

### Investments

The Invest tab runs on a quant engine I wrote in Python. Each weekday it forecasts risk, sets an outlook from today's yields and valuations, measures factor exposures and stress tests, then issues recommendations with a stated confidence. Each one is scored once it matures, and a confidence level is demoted when its hit rate falls short. The Sandbox replays past recommendations on the actual portfolio, after taxes and trading costs, to show what following them would have done. Written notes sit on top under the same rule as the spending report, and nothing trades by itself.

## RaiClimbing

Each session type owns a roster of exercises dosed per week, and every logged set records its load, count and whether it was done. A pain check-in before each session is scored for red flags, which trim the next loading session. Climbs come in from the Tension Board API and feed a grade pyramid.

History syncs to Supabase as one versioned document, so a reinstall or an older build can't overwrite newer data.

An LLM reads an aggregate of my plan, sessions, climbs and pain check-ins and returns strict JSON with up to eight recommendations. Some carry a one-tap change to the plan, like a new load for an exercise. A server-side validator rejects any recommendation that doesn't state its proposed values in its own text, so a tap only applies what I already read.
