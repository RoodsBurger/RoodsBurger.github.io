# Site Refresh — Phase 5: Chat Assistant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the site chat accurate (new third-person index, rerank, grounded documents), safe (origin check, rate limit, daily cap, role-restricted history, private healthcheck), and responsive (streamed replies).

**Architecture:** Pure, unit-tested TypeScript modules in `v2/src/lib/chat/` (schema, prompts, retrieval selection, rate-limit decisions, origin checks, model constants). A Netlify Functions v2 handler `v2/netlify/functions/chat.mts` wires them to Cohere (embed-v4.0 1024d, rerank-v4.0-fast, command-a-03-2025 via `chatStream`) and Pinecone (namespace constant). Rate-limit counters live in Netlify Blobs behind a small store interface with an in-memory implementation for local runs and tests. The widget reads a streamed text body and renders sanitized markdown incrementally.

**Tech Stack:** Node 22 (native TS type stripping for tests), Netlify Functions v2, `@netlify/blobs`, `cohere-ai` 7.21, `@pinecone-database/pinecone` 5.1, zod, `dompurify`, React 19.

**Spec:** `docs/superpowers/specs/2026-09-25-site-refresh-design.md` §5

## Global Constraints

- Models (single source of truth `v2/src/lib/chat/models.ts`): `EMBED_MODEL = "embed-v4.0"`, `EMBED_DIM = 1024`, `RERANK_MODEL = "rerank-v4.0-fast"`, `CHAT_MODEL = process.env.COHERE_CHAT_MODEL || "command-a-03-2025"`, `NAMESPACE = process.env.PINECONE_NAMESPACE || "<current namespace constant>"`. The indexer imports the same module.
- No Netlify dashboard changes are required for the default path: defaults live in code. `HEALTHCHECK_TOKEN` is optional; without it, the detailed healthcheck is disabled.
- History: roles `user | assistant` only; each ≤ 2000 chars; last 12 messages.
- Rate limit: 20 requests / 10 min per IP; global 1500 requests / UTC day. Over limit → HTTP 429 with a short friendly message; the widget shows it.
- Retrieval: Pinecone topK 20 → rerank → keep results with relevance ≥ 0.30, max 4; boost (+0.15 before thresholding) results whose `slug` equals the page slug.
- Public errors are generic (`{ error: "..." }`), details only in `console.error`.
- Upstream timeouts: embed 6 s, Pinecone 6 s, rerank 6 s, chat stream first byte 10 s.
- The popover and site UI behavior are unchanged apart from the chat widget rendering streamed text.
- Code comments single line, current behavior. Stage explicit paths. Commits end with the co-author trailer.

### Task 2: Functions v2 handler with streaming and hardening

- [ ] `chat.mts`: `export default async (req: Request) => Response`; `export const config = { path: "/.netlify/functions/chat" }`.
  - OPTIONS → 204 with CORS for allowed origins.
  - GET `?healthcheck=<token>`: if `HEALTHCHECK_TOKEN` set and matches → run embed + describeIndexStats (namespace count) and return details; else return `{ status: "ok" }` with no upstream calls.
  - POST: origin check (403), parse schema (400 generic), rate limit via Blobs store `getStore("chat-rate")` keyed `ip:<x-nf-client-connection-ip>:<window>` and `day:<YYYY-MM-DD>` (429), fast path → stream the fast-path reply, else embed (search_query, embed-v4.0, 1024) → Pinecone namespace query topK 20 → rerank → `selectDocuments` → `cohere.chatStream({ model, messages, documents, temperature: 0.3 })` → `ReadableStream` of UTF-8 text deltas (`content-delta` events), `Content-Type: text/plain; charset=utf-8`, `Cache-Control: no-store`. Stream errors after start append "\n\n(Sorry, the reply was cut off.)" and close.
  - All upstream calls wrapped with `AbortSignal.timeout` per constraints.
  - If Blobs is unavailable (local run without Netlify context), fall back to `memoryStore()`.
- [ ] Delete `chat.ts`. Add deps: `npm i dompurify @netlify/blobs` (pin versions from npm view), `@types/dompurify` if needed.
- [ ] Local verification script `scripts/eval-chat.mjs`: imports the handler, builds `Request` objects with `Origin: http://localhost:4321`, runs ~15 fixed questions (each project, current role, education, hobbies, greetings, off-topic, a prompt-injection attempt, a question with `pageSlug` set), prints streamed answers and retrieved ids. Uses `.env` keys via `--env-file`.
- [ ] Run `node --env-file=.env scripts/eval-chat.mjs`; review answers (controller). `npm run build` (astro check covers types). Commit "Stream chat replies through a hardened Functions v2 handler".
